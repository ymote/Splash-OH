# flutter/samples on OpenHarmony

The same `components/flutter/` kit that Splash-Makepad renders to makepad
widgets, walked into **native ArkUI** here. One `.splash` source, two unrelated
native toolkits — which is the point of the `UiNode` split.

```sh
./build.sh          # cargo -> stage .so -> hvigor -> install -> launch
```

The kit is vendored to `crates/splash-oh-native/assets/flutter.splash`,
generated by Splash-Makepad's `assemble` example:

```sh
cd ../Splash-Makepad
cargo run -q -p splash-makepad --example assemble -- components/flutter \
  > ../Splash-OH/crates/splash-oh-native/assets/flutter.splash
```

`dsl::build_flutter(route, dark)` evaluates it; `app.screen` carries the route,
and `catalogScreen(name)` drives one directly for a capture sweep.

## What the ArkUI backend had to grow

The kit is authored against the makepad backend's richer attribute set, so the
walker gained the rest of that vocabulary. Three of these were not translations
but genuine mapping bugs — each rendered something plausible and wrong:

| kit attribute | ArkUI mapping | note |
|---|---|---|
| `fillw` / `fillh` | `LAYOUT_WEIGHT` along the parent's main axis, `WIDTH_PERCENT`/`HEIGHT_PERCENT` across it | **mapping both to 100% made every child of a row demand the whole row** — the second stat tile vanished off the edge |
| `spacing` | trailing margin on every child but the last | ArkUI's Column/Row take their gap at construction, which the node API does not expose |
| `padx` / `pady` | 4-value `NODE_PADDING` | |
| `alignx` / `aligny` | `ROW_/COLUMN_ALIGN_ITEMS` + `JUSTIFY_CONTENT` | **ArkUI's Column centres its children; Flutter and makepad start them** — every screen came out centre-aligned until the default was pinned to START |
| `elevation` | `NODE_SHADOW`, scaled as the makepad backend scales it | |
| `icon` | nearest system glyph (see below) | |
| `tapto` | route string interned to an i32 tap id | ArkUI events carry a number, the kit names routes with strings |

And one structural fix, not an attribute at all:

> **ArkUI's `Scroll` takes exactly one child.** Everything after the first is
> dropped. The DSL — like Flutter and makepad — lets a scrolling area hold a
> list, so the walker now wraps multiple children in a Column. Before this the
> index rendered its header and nothing else.

### Taps

`tapto` interns its route string to an i32 the ArkUI click event can carry, and
`on_event` turns it back into a route. That check has to run **first**, ahead of
the `WECHAT_ACTIVE` hand-off to the bridge router — `catalogScreen` sets that
flag when it mounts, and the branch returns unconditionally, so every tap in the
kit was handed to a router that knows nothing about route strings and then
dropped on the floor. Nothing was clickable until the check moved up.

Verified on device: index -> a sample screen -> back.

### Icons

Font Awesome ships with the makepad theme; OpenHarmony has no such font, and
FA's codepoints sit in the Private Use Area. Pointing `font-family` at a font
that is not there rendered every icon as *nothing* — invisible chevrons, empty
FABs. `icon_fallback` substitutes the nearest glyph HarmonyOS Sans actually has
(`‹` `›` `+` `✓` `★` …). Approximate, but visible. Shipping the real face as a
rawfile and registering it is the better fix and is not done.

## Per-widget QC, round 2 (verified on device)

The first round matched dimensions. This round fixed widgets that were not
behaving as widgets — each found by looking at the OH phone, none catchable by
the route sweep:

| defect | cause | now |
|---|---|---|
| **declared control state never reached the widget** | the makepad emitter never forwarded `on`/`value`/`total` at all, and ArkUI set `NODE_PROGRESS_VALUE` on a *slider* | both backends forward it; `active` on checkbox/toggle/radio (makepad's `CheckBox` field), `NODE_SLIDER_VALUE` + pinned 0..1 range on ArkUI |
| **checkbox drew as a circle** — indistinguishable from a radio | ArkUI's default checkbox shape is CIRCLE | `NODE_CHECKBOX_SHAPE` = ROUNDED_SQUARE, sized 18 per Flutter's `_kEdgeSize` (`material/checkbox.dart:650`) |
| **radio was the wrong size** | never sized | 16 across, per `_kOuterRadius` 8 (`material/radio.dart:31`) |
| **progress indicators were solid purple boxes** | `bg` means "arc colour" on makepad but "background fill" on ArkUI — the same DSL meant two different things | `bg` maps to `NODE_LOADING_PROGRESS_COLOR`/`NODE_PROGRESS_COLOR` on progress nodes; Flutter's indicator is an arc on nothing |

Still wrong, and honestly so: the radio's checked indicator is a **tick**, not
Material's dot, and it is system blue rather than M3 primary. This SDK exposes
no radio indicator-type attribute, and `NODE_RADIO_STYLE` takes three packed
colours that the current `u32_attr` cannot set.

## cupertino_gallery, rewritten against its own source

The gallery was the weakest part of the port and was called out as "basically
not implemented". It was: the 21 rows were right, but the detail pages behind
them were invented. The Button page showed "Filled / Tinted / Plain / Disabled";
the real `button_page.dart` shows **"CupertinoButton widget"** with Enabled and
Disabled, then **"CupertinoButton.filled widget"** with Enabled and Disabled.
List Tile showed Wi-Fi/Bluetooth/Cellular; the real `list_tile_page.dart` has
**two sections of three Title/Subtitle tiles** with leading icons and forward
chevrons. Radio showed two bare radios; the real page is **three list tiles with
leading radios**, first selected.

All 21 pages are now transcribed from `cupertino_gallery/lib/widgets/*.dart` —
same labels, same controls, same initial values (`switch_page` starts ON,
`checkbox_page` OFF, `slider_page` at 0.5, `picker_page` shows One/Two/Three,
`segmented_control_page` One/Two/Three, `text_theme_page` its three sample
lines, `scrollbar_page` its "Item N" rows). Six pages that were previously just
a note — Action Sheet, Sheet, Popup Surface, Context Menu, Scrollbar, Sliding
Segmented Control — now render their real content, with the note kept only where
a route or gesture genuinely cannot be drawn.

The route sweep now asserts on the **Flutter strings** rather than on my own
invented ones, so the pages are pinned to the sample rather than to whatever I
happened to write.

## Animation

The DSL has no tween, curve, controller or animator, and a tree is evaluated
once per mount — so nothing in a screen can move on its own. What the design
does leave open is the host's frame loop: **`st.t` is a clock, and a screen
recomputes itself against it**. That is animation by the only route available
here, and all twenty demos in the `animations` sample now use it.

The curves live in `_kit.splash` because Flutter's `Curves` are not available:
`ease`, `ease_in_cubic`, `ease_out_cubic`, `ease_in_expo`, `ease_out_expo`,
`bounce_out`/`bounce_in` (transcribed from Flutter's own piecewise definition),
a damped `spring`, plus `lerp`, `lerp_argb` and `fade`. There is no `pow` or
`cos` in the VM, so those are computed by squaring and by series.

Each demo is its own effect, at its own duration, from its own source file:

| demo | effect | from |
|---|---|---|
| AnimatedContainer | size, colour and corner together | 400ms |
| PageRouteBuilder | a page sliding up | `Offset(0,1)->zero`, Curves.ease |
| AnimationController | the raw 0..1 value | 1s |
| Tweens | counting to 1,000,000 | `Tween(begin: 0.0, end: 1000000)` |
| AnimatedBuilder | deepPurple -> deepOrange | 800ms ColorTween |
| Custom Tween | **text typing itself out** | TypewriterTween, 3s |
| TweenSequence | through seven colours | equal weights, 3s |
| FadeTransition | opacity 1 -> 0 | 500ms, Curves.easeIn |
| Expandable Card | card grows | 300ms, easeInOutCubic |
| Carousel | centre item scaled | Curves.easeOut |
| Focus Image | rect expanding to fill | Curves.ease |
| Card Swipe | dismiss right, spring back | `Offset.zero -> Offset(1,0)` |
| Flutter Animate | fade -> slide -> scale, chained | staggered |
| Repeating | BorderRadius 100 -> 0 | 2s, reversing |
| Spring Physics | damped oscillation to centre | SpringDescription |
| AnimatedList | rows in and out | 300ms in / 600ms out |
| AnimatedPositioned | travels between corners | 1s |
| AnimatedSwitcher | one child scales out, next in | 1s |
| Hero | flies and grows, 50 -> 200 | |
| CurvedAnimation | six named curves side by side | 4s |

`every_animation_demo_moves_and_is_its_own` pins both properties: each demo's
output must change across several sample times (a single pair can coincide —
`pingpong` over 1.2s is 0.5 at both t=0.3 and t=0.9), and all twenty rendered at
one instant must be twenty different frames, so none can quietly fall back to a
shared effect.

On device, ArkTS calls `animTick()` at 30fps; it returns false without work on
every static screen, so only the animation demos cost anything. Verified on the
OH phone: the TweenSequence cycling yellow -> green -> blue.

## Known gaps

- Icons are substituted glyphs, not the real face.
- The QC pass covers the widgets whose metrics are pinned in the Flutter source
  above. Others (SnackBar, Slider track, TextField internals, segmented control)
  have not been sourced yet.
- `START_APP` in `deveco/.../Index.ets` is `catalog`, and `App::Catalog` now
  builds the flutter kit rather than `assets/catalog.splash`. The Material
  catalog is still there and still builds; nothing routes to it.
